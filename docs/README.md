# DispatcherARM — АРМ диспетчера службы доставки

WPF-приложение (.NET 8) для автоматизации работы диспетчера: заказы, маршруты,
водители, автопарк, финансы и оптимизация маршрутов.

## Запуск в Visual Studio (Windows)

**Что нужно установить**
- **Visual Studio 2022 версии 17.8 или новее** (Community бесплатна).
  В установщике отметьте рабочую нагрузку **«Разработка классических приложений .NET»**,
  в неё входит .NET 8 SDK. Версию VS можно посмотреть в «Справка → О программе»;
  если она ниже 17.8, обновите её через Visual Studio Installer.
- Windows 10/11 (WebView2 Runtime для клиентского портала уже есть в системе).
- Docker и PostgreSQL **не нужны**: по умолчанию используется SQLite.

**Запуск**
1. Распакуйте архив, например в `C:\Users\<имя>\Desktop\проект диплом`.
2. Двойной щелчок по `DispatcherARM.sln` (или в VS «Файл → Открыть → Проект/решение»).
3. Дождитесь, пока VS восстановит NuGet-пакеты (строка состояния внизу; при первом
   открытии нужен интернет, это займёт 1–3 минуты).
4. Запускаемый проект — **DispatcherARM.UI** (выделен жирным в «Обозревателе решений»).
   Если это не так: ПКМ по DispatcherARM.UI → «Назначить запускаемым проектом».
5. Нажмите **F5** (или зелёную кнопку ▶).

**Учётные записи демо-базы**

| Роль | Логин | Пароль |
|---|---|---|
| Администратор | `admin` | `admin123` |
| Диспетчер | `dispatcher` | `disp123` |
| Водитель | `driver1` / `driver2` / `driver3` | `driver123` |

База создаётся автоматически при первом запуске:
`%LocalAppData%\DispatcherARM\dispatcher_arm.db`. Чтобы начать с чистых демо-данных,
закройте программу и удалите этот файл.

**Тесты:** «Тест → Обозреватель тестов → Запустить все» (155 тестов).

**Если не собирается**
- *NETSDK1045: текущий пакет SDK не поддерживает .NET 8.0.* Обновите VS до 17.8+ или
  установите .NET 8 SDK с https://dotnet.microsoft.com/download/dotnet/8.0
- *NETSDK1004: файл ресурсов "...\\obj\\project.assets.json" не найден.* Пакеты не восстановлены.
  ПКМ по решению → «Восстановить пакеты NuGet» → «Пересобрать решение». Или в «Вид → Терминал»:
  `dotnet restore DispatcherARM.sln`, затем «Сборка → Пересобрать решение».
  Ещё проще — двойной щелчок по `build_and_run.bat` в корне проекта: восстановит пакеты, соберёт и запустит.
  Также проверьте «Средства → Параметры → Диспетчер пакетов NuGet → Общие»: должны быть отмечены
  «Разрешить NuGet загружать отсутствующие пакеты» и «Автоматически проверять отсутствующие пакеты при сборке».
  Текст ошибки восстановления VS показывает в «Вид → Вывод → Показать выходные данные из: Диспетчер пакетов».
- *Не удаётся найти пакет / ошибки NuGet.* ПКМ по решению → «Восстановить пакеты NuGet»,
  проверьте источник nuget.org в «Средства → Параметры → Диспетчер пакетов NuGet → Источники».
- *«Проект с типом выходных данных "Библиотека классов" не может быть запущен».*
  Назначьте запускаемым DispatcherARM.UI (п. 4).
- Странные ошибки после копирования проекта с другого компьютера: закройте VS, удалите
  папки `bin`, `obj` и `.vs`, откройте решение заново.

## Маршруты и OSRM

Маршруты строятся через публичный OSRM (`router.project-osrm.org`), а при его недоступности через резервный сервер `routing.openstreetmap.de`. Без интернета маршрут рассчитывается офлайн: порядок объезда корректный, километраж приблизительный (по прямой ×1,3). Состояние сервера показано в правом нижнем углу главного окна.

## Назначение, калькулятор и стоимость работ

- **Заказы → «Назначить»:** выберите водителя и ТС. Калькулятор сразу покажет пробег (депо → клиент → депо), топливо, оплату водителю, накладные, стоимость работ и прибыль.
- **Маршруты → «Построить маршрут»:** отметьте заказы, нажмите «Рассчитать» (порядок объезда, километраж, стоимость рейса), затем «Назначить».
- **Путевой лист и ТТН** содержат раздел «Стоимость выполненных работ» (план до завершения, факт после) с итогом прописью. Документы сохраняются в Word (RTF), TXT или печатаются.
- **Отчёты → «Стоимость выполненных работ»:** рейсы и заказы за период, итоги, экспорт в Excel/CSV.
- Тарифы (цена топлива, комиссия водителя, накладные, значения по умолчанию) задаются в «Настройках». Ставки водителя — в его карточке, расход топлива — в карточке ТС.

## Пароли, премии, штрафы и зарплата

- **Сменить пароль:** меню пользователя → «Сменить пароль».
- **Сбросить пароль** (администратор → «Пользователи»): программа выдаст временный пароль и скопирует его в буфер обмена. При входе пользователь обязан сменить его на свой.
- **Премия / штраф:** «Водители» → выбрать водителя → «Премия / штраф» (или администратор → «Пользователи»). Сумма сразу попадает в кошелёк водителя и в зарплатную ведомость.
- **Расчёт зарплаты:** «Водители» → «Расчёт зарплаты». Итого = оклад + за заказы + премии − штрафы, с детализацией и экспортом в Excel/CSV. Окно оформлено как расчётный листок; администратор может удалить ошибочную операцию или исправить её сумму (с указанием причины, запись в журнал).
- **Вывод средств** (водитель → «Кошелёк»): от 100 ₽, в пределах баланса.

Старую базу удалять не нужно: новые столбцы добавляются автоматически при запуске.

## Права администратора (карточка водителя)

«Водители» → выбрать водителя → **«Карточка»** (или двойной щелчок). У администратора в карточке есть:

- **Финансы:** «Удалить операцию» и «Изменить сумму» для любой выплаты, начисления, премии или штрафа. Баланс пересчитывается сразу.
- **История маршрутов:** «Удалить маршрут». Невыполненные заказы возвращаются в «Новые», выполненные остаются. По желанию можно удалить и начисления за рейс.
- **Управление:** «Снять заказ» / «Снять все заказы», статус водителя (отпуск, отстранение), «Заблокировать вход» (в программу и в приложение на телефоне), «Открепить ТС», «Где сейчас водитель», «Удалить водителя» (по желанию вместе с историей).
- Для каждого действия нужно указать причину. Она записывается в **журнал действий администратора** (таблица `audit_log`): кто, когда, что сделал и почему.

Диспетчер видит карточку только для чтения.

## Заказы из 1С

Заказы поступают из 1С, а не через веб-форму. Есть два способа:

1. **HTTP (рекомендуется).** «Интеграция» → «Обмен с 1С по HTTP»:
   - скопируйте адреса и ключ API;
   - кнопка **«Сохранить модуль для 1С (.bsl)»** создаёт общий модуль `ОбменСАРМДиспетчера`, в который уже подставлены адрес, порт и ключ;
   - в конфигураторе 1С создайте общий модуль, вставьте текст и вызывайте `ОтправитьЗаказы(...)`, `ОтправитьЗаказВДоставку(Документ)`, `ЗагрузитьСтатусыДоставки()`, `ГдеЗаказ(Номер)`.
   - Кнопка **«Проверить»** отправляет тестовый заказ самой себе.
   - API: `POST /api/1c/orders`, `GET /api/1c/statuses?since=…&format=xml`, `GET /api/1c/track?externalId=…`. Ключ передаётся в заголовке `X-Api-Key`.
2. **Через папку обмена (XML/JSON).** Файлы подхватываются автоматически, а на странице «Заказы» есть кнопка **«Загрузить из 1С»**.

Текст модуля лежит также в `docs/1C/ОбменСАРМДиспетчера.bsl`. В нём вместо адреса стоят метки `{{HOST}}`, `{{PORT}}` и `{{KEY}}`.

## Приложение водителя и трекинг (как Яндекс Доставка)

- Меню **«Трекинг водителей»** → «Запустить». Водитель открывает на телефоне показанный адрес (`http://<IP-компьютера>:5080/`) и входит под своим логином (driver1 / driver123).
- В приложении водитель видит свои доставки: **состав груза** (товары, артикулы, количество), вес, объём, стоимость товара, сумму, которую нужно получить с клиента, маршрут в Яндекс Картах и звонок клиенту. Кнопки: «Начать погрузку» → «Выехал к клиенту» → «Товар передан». Координаты отправляются каждые 10 секунд.
- Диспетчер видит водителей на карте, расстояние и время прибытия к текущему заказу. Поиск **«Где заказ?»** работает по номеру или коду 1С. На странице «Заказы» есть кнопка **«Где заказ»**.
- **Доступ с телефонов:** один раз запустите от администратора `Открыть_доступ_для_телефонов.bat` (лежит рядом с exe). Он открывает порт 5080 в брандмауэре и разрешает программе его слушать. Компьютер и телефон должны быть в одной сети Wi‑Fi.
- **GPS телефона** браузеры отдают только по HTTPS. В локальной сети по http приложение предложит режим **«Имитация движения»**. Для настоящего GPS и для водителей вне Wi‑Fi — **«Доступ из интернета»** (ниже).
- Точки старше 30 дней удаляются автоматически.

## Доступ из интернета и постоянный адрес (GitHub Pages)

**Доступ из интернета** («Трекинг водителей» → «Доступ из интернета» → «Включить»):
- программа сама скачивает (один раз, ~55 МБ) и запускает бесплатный туннель Cloudflare, регистрация не нужна;
- появляется адрес `https://….trycloudflare.com`. Он открывается с любого телефона через мобильный интернет, и по HTTPS работает GPS;
- этот адрес меняется при каждом включении.

**Постоянный адрес на GitHub Pages** — `https://kosarev54.github.io/diplom/`. Настраивается один раз:
1. Репозиторий на GitHub должен быть **публичным** (бесплатный Pages работает только так).
2. «Трекинг водителей» → **«GitHub Pages…»** → «Создать токен». Откроется GitHub с уже отмеченным правом `repo`. Нажмите *Generate token* и скопируйте `ghp_…`.
3. Вставьте токен, проверьте репозиторий (`kosarev54/diplom`) и нажмите **«Опубликовать приложение»**. Программа сама положит страницу в `docs/index.html` репозитория и включит Pages (из папки `/docs`). Сайт появится через 1–2 минуты (при первом включении — до 10).
4. Включите «Доступ из интернета». Программа запишет текущий адрес туннеля в `docs/server.json`, и страница на GitHub найдёт программу сама.

Водителям достаточно один раз отправить ссылку `https://kosarev54.github.io/diplom/`. При закрытии программы адрес очищается, и приложение покажет «Программа диспетчера сейчас не в сети».

Без токена тоже можно: кнопка «Копировать ссылку» даёт ссылку вида `…github.io/diplom/?server=https://…trycloudflare.com`. Её нужно отправлять заново после каждого перезапуска.

Если удобнее вручную: скопируйте `docs/index.html` из проекта в репозиторий и включите *Settings → Pages → Deploy from a branch → main → /docs*.

Токен хранится только на этом компьютере в зашифрованном виде (Windows DPAPI). Вход в приложение защищён паролем водителя, API 1С — ключом.

## Запуск из командной строки

```bat
dotnet build DispatcherARM.sln -c Release
dotnet run --project src\DispatcherARM.UI\DispatcherARM.UI.csproj
dotnet test
```

PostgreSQL (необязательно): `docker compose -f docker/docker-compose.yml up -d`,
затем `App.UsePostgres = true` в `App.xaml.cs`.
