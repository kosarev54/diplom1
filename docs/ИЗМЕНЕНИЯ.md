# DispatcherARM — что исправлено и доработано

Сборка: `dotnet build DispatcherARM.sln -c Release` — **0 ошибок, 0 предупреждений**.
Тесты: `dotnet test` — **270 тестов, все проходят** (раньше: 17 тестов, которые проверяли копию логики, а не настоящий код).

> **Открытие в Visual Studio:** двойной щелчок по `DispatcherARM.sln` → F5 (подробно — в README.md).
> Запускаемым по умолчанию теперь назначен проект `DispatcherARM.UI`.
>
> Старую базу `%LocalAppData%\DispatcherARM\dispatcher_arm.db` удалять не нужно:
> при запуске `SchemaUpgrader` сам добавляет новые столбцы (себестоимость, ТС заказа) и индексы,
> а `DataConsistencyService` исправляет старые «битые» связи. Новые ограничения (уникальный `ExternalId`,
> запрет каскадного удаления транзакций) в полном объёме действуют только в новой БД.

## 3. Найденные и исправленные ошибки

**Деньги**
- Подтверждение заказа можно было нажать дважды и начислить водителю 2 раза. Теперь заказ перечитывается из БД, есть проверка `HasEarningForOrderAsync`, всё сохраняется одной транзакцией.
- В зарплатной ведомости баланс считался как *начисления − выводы*, без штрафов и бонусов. Теперь везде одна формула: `PayrollCalculator.CalculateBalance`.
- При удалении водителя каскадно удалялась вся его финансовая история. Теперь `DeleteBehavior.Restrict`, а на странице «Водители» предлагается перевести водителя в статус «Отстранён».
- Для всех денежных полей задана точность `decimal(18,2)`.

**Заказы**
- `OrderNumber` был ограничен 20 символами, а номер вида `ORD-WEB-20261117143000-001` длиннее, поэтому в PostgreSQL заказ не сохранялся. Теперь единый формат `ORD-<источник>-ггММдд-0001` (`OrderNumberGenerator`), номера продолжают уже имеющиеся в БД, длина поля 32.
- При отмене заказа водитель оставался «в рейсе». Теперь он освобождается, если других активных заказов нет.
- В круговой диаграмме статусов статус «Погрузка» выходил за границы массива цветов. Теперь сопоставление идёт по значению enum.

**Интеграция с 1С**
- Логика перенесена из UI в `DispatcherARM.Application`, поэтому её можно тестировать.
- Защита от дублей проверялась по неправильной переменной. Теперь она работает и между файлами, и внутри одного файла (+ уникальный индекс `ExternalId`).
- Файл с ошибкой оставался в папке. Теперь он переносится в `failed/`, успешный в `processed/`.
- Дата разбиралась по региональным настройкам Windows. Теперь `yyyy-MM-dd` / `dd.MM.yyyy` через InvariantCulture.
- XML: запрещены DTD (защита от XXE), принимается и запятая, и точка в числах.
- Ручной импорт поддерживает JSON **и XML**.
- Папка обмена хранилась в двух местах (`Properties.Settings` и `AppSettings`). Теперь используется одно (`IntegrationFolder`), старое значение переносится автоматически.

**Документы**
- «Сохранить в Word» копировал RTF-текст в файл `.docx`, который Word не открывал. Теперь сохраняется настоящий `.rtf` (или `.txt`), после сохранения файл можно сразу открыть.
- `LicenseNumber[..^6]` падал на коротких номерах ВУ. Теперь серия и номер разбираются безопасно (`SplitLicense`).
- Реквизиты организации в путевом листе и ТТН были зашиты в код (ИНН «7701000001», «ул. Складская»). Теперь они берутся из «Настроек». Вид топлива зависит от типа ТС.
- Заглушка «—» в RTF превращалась в «?». Исправлено.

**Прочее**
- Координаты депо в расчёте даты доставки больше не зашиты: берутся из настроек (`IDepotProvider`).
- Порт веб-сервера заявок берётся из настроек, а не константы 5050.
- В маршруте показывается стоимость топлива в рублях (литры × цена из настроек).
- При выходе из программы останавливается мониторинг папки 1С.

## 5. Что можно сказать на защите

- **Архитектура:** бизнес-логика (1С, расчёты, отчёты) вынесена из окон WPF в слой Application, поэтому её покрывают автотесты без запуска интерфейса.
- **Надёжность:** денежные операции защищены от повторного начисления и выполняются атомарно, финансовая история не удаляется.

## Маршрутизация OSRM (ошибка «Не удалось получить оптимальный маршрут от OSRM Trip API»)

- **Причина:** публичный сервер `router.project-osrm.org` отвечает **403 Forbidden** на запросы без заголовка `User-Agent`, а `HttpClient` в .NET по умолчанию его не отправляет. `OsrmClient` при этом проглатывал любую ошибку и возвращал `null`, поэтому было видно только общее сообщение.
- `OsrmClient` теперь отправляет `User-Agent: DispatcherARM/1.0 …` и сохраняет понятную причину сбоя в `LastError` (403, 429, таймаут, нет сети, код OSRM `NoRoute`).
- Если основной сервер недоступен, автоматически используется резервный публичный сервер `routing.openstreetmap.de/routed-car` (FOSSGIS, тот же API). Если в настройках выбран локальный сервер, на публичный клиент не переключается.
- **Офлайн-режим.** Без интернета маршрут всё равно строится: расстояние считается по прямой (формула гаверсинусов) ×1,3, время берётся при средней скорости 30 км/ч, порядок объезда определяется методом ближайшего соседа с улучшением 2-opt. Пользователь видит предупреждение, что километраж приблизительный.
- Алгоритмы (ближайший сосед, 2-opt, матрица, подсчёт длины) вынесены в `RoutePlanner` и покрыты тестами. В 2-opt добавлена проверка полной длины маршрута, потому что матрица OSRM несимметрична (односторонние улицы).
- Если OSRM Route API не ответил, километраж маршрута теперь берётся из матрицы. Раньше в этом случае сохранялось 0 км.
- Адреса OSRM со страницы «Настройки» реально применяются, и перезапуск не нужен. Раньше они сохранялись, но клиент маршрутизации их не использовал.
- В строке состояния показывается фактическая доступность OSRM (/). Причина сбоя выводится во всплывающей подсказке.

## Редизайн, связи, калькулятор маршрута и стоимость работ

### Оформление и окна
- Новая спокойная палитра (`Themes/AppTheme.xaml`): индиго `#4F6BED` + бирюзовый акцент, светлый фон `#F4F6FB`, мягкие статусные цвета (успех/предупреждение/ошибка/инфо). Все цвета — именованные ресурсы. Около 550 жёстко заданных цветов в 30+ окнах заменены на ресурсы палитры, в том числе цвета в коде (`ThemeColors`).
- Единые стили: `Card`, `SoftPanel`, `PageTitle`, `SectionTitle`, `Caption`, `MetricValue`, кнопки `Primary/Secondary/Success/Danger/Accent/GhostButton`.
- Новое главное окно: тёмная боковая панель с группами разделов, шапка с градиентом и именем пользователя, строка состояния.
- **Все окна видны целиком** (`WindowFitter`). Любое окно при открытии получает владельца (не прячется за главным), ограничивается рабочей областью экрана (без панели задач), центрируется. Если содержимое не помещается, появляется прокрутка. Это важно для ноутбуков 1366×768 и масштаба 125–150 %.

### Связи между данными
- Заказ теперь хранит назначенное ТС (`AssignedVehicleId`), плановый пробег и себестоимость. Маршрут хранит выручку, топливо, оплату водителю, накладные и итоговую стоимость.
- `OrderWorkflowService` — единые правила переходов статусов заказа: назначение, «взял в работу», доставка, отмена. Начисление водителю выполняется ровно один раз и равно его доле в себестоимости. Отмена снимает заказ с маршрута, а когда закрыта последняя точка, маршрут автоматически завершается.
- `RouteService`: построение, сохранение, старт, завершение и отмена рейса. Связи «маршрут ↔ точки ↔ заказы ↔ водитель ↔ ТС» обновляются одним сохранением (атомарно). Водитель/ТС освобождаются после завершения.
- `DataConsistencyService` при запуске исправляет старые несоответствия: заказ «Назначен» без водителя, точки отменённых заказов, «зависшие» маршруты, отсутствующая себестоимость.
- В таблице заказов появились столбцы «Себест.», «ТС», «Маршрут». В карточке маршрута для точек показываются статус заказа и себестоимость.

### Калькулятор маршрута при назначении
- **Назначение заказа** (`AssignOrderDialog`): при выборе водителя и ТС стоимость пересчитывается сразу. В расчёте участвуют пробег (депо → клиент → депо, по OSRM или приблизительно), топливо, оплата водителю, накладные, итог и прибыль. Тут же проверяется перегруз ТС. Рассчитанная себестоимость сохраняется в заказе.
- **Построение маршрута** (`BuildRouteDialog`) — в два шага: «Рассчитать» (оптимальный порядок, километраж, стоимость рейса и каждого заказа, предупреждения о перегрузе) → «Назначить». Водитель видит ту же сумму, которую получит.
- Страница «Маршруты» переписана: фильтры, итоги, столбцы стоимости и прибыли, кнопки старт/завершить/отменить/путевой лист.
- Отдельный «Калькулятор стоимости» считает по той же формуле (`Application/Costing/RouteCostCalculator`), что и назначение, и берёт тарифы из «Настроек». Добавлены выручка, прибыль, рентабельность и себестоимость 1 км.
- В «Настройках» появились накладные расходы (%), расход топлива и ставка за доставку по умолчанию. Значения проверяются при сохранении.
- В карточке маршрута убрана зашитая в код цена топлива «55 ₽/л». Финансовые показатели берутся из калькулятора.

**Формула** (покрыта тестами):
топливо = км × расход ТС / 100 × цена;
водителю = км × ставка за км + доставки × ставка за доставку + комиссия × выручка;
накладные = % × (топливо + водителю);
стоимость работ = топливо + водителю + накладные; прибыль = выручка − стоимость работ.

### Стоимость выполненных работ в документах и отчётах
- **Путевой лист:** новый раздел «6. Стоимость выполненных работ». В нём перечислены точки рейса с себестоимостью каждой, пробег, топливо (литры и рубли), оплата водителю, накладные, итог, выручка, прибыль и итог прописью. Путевой лист можно сформировать на весь рейс (из «Маршрутов»). Туда попадают все точки и возврат в депо, ТС берётся из рейса/заказа, номер документа постоянный. До завершения раздел помечен «(ПЛАН)», после завершения — «фактически выполненные работы».
- **ТТН:** раздел «Стоимость выполненных работ по перевозке», итог груза прописью, товарные позиции заказа (раньше не загружались).
- Раздел одинаково выводится на экран, в RTF (Word), TXT и на печать (`WorkCostRenderer`). Исправлено двойное экранирование кириллицы в RTF ТТН.
- **Отчёты:** новый блок «Стоимость выполненных работ» за период (этот/прошлый месяц или произвольный), с флажком «только выполненные». Строки — рейсы и разовые заказы; суммы — пробег, топливо, оплата водителю, накладные, стоимость работ, выручка и прибыль. Есть итоги и экспорт в Excel/CSV. В общем экспорте заказов добавлены себестоимость, прибыль, ТС и маршрут. Пробег в зарплатной ведомости берётся из расчёта, а не по формуле «заказы × 25 км».

## Пароли, оплата водителям, премии и штрафы

### Смена и сброс паролей
- Единые правила пароля (`PasswordPolicy`): не короче 6 символов, есть буква и цифра, без пробелов, не совпадает с логином. Они действуют при регистрации, смене и сбросе пароля. Новый пароль должен отличаться от текущего.
- **Сброс пароля администратором.** Раньше пароль был предсказуемым (`Pass{id}!{секунда}`), и его легко было угадать. Теперь создаётся криптостойкий временный пароль из 10 символов, без похожих символов 0/O/1/l. Пароль копируется в буфер обмена. Перед сбросом запрашивается подтверждение.
- **Обязательная смена временного пароля.** После сброса пользователь при входе сразу видит окно смены пароля и не попадёт в программу, пока не задаст свой. Новый признак `User.MustChangePassword` в старой базе создаётся автоматически.
- Окно «Смена пароля» больше не обрезается: кнопки «Сохранить/Отмена» раньше не помещались в окно высотой 300 px. Все проверки выполняет `AuthService`.
- Администратор не может заблокировать сам себя или последнего активного администратора.

### Премии и штрафы
- Новый сервис `DriverFinanceService` — единое место для операций с деньгами водителя. Запись в журнал и пересчёт баланса кошелька идут вместе.
- **Исправлен разбор суммы:** при вводе «500,50» раньше начислялось **50 050 ₽**, потому что запятая считалась разделителем тысяч. Теперь принимаются «1500», «1 500», «1500,50», «1500.50».
- Сумма ограничена 1 000 000 ₽ (защита от лишнего нуля), причина обязательна. Перед проведением запрашивается подтверждение. Если штраф больше баланса, программа предупреждает об этом.
- В операции записывается автор: «(назначил: admin)». Раньше автор всегда был неизвестен — страница администратора брала пользователя из службы, в которую никто не входил. Теперь вошедший пользователь хранится в `App.CurrentUser`.
- «Премия / штраф» есть не только у администратора, но и на странице «Водители» и в окне «Расчёт зарплаты», поэтому ими может пользоваться диспетчер.
- В кошельке водителя показаны премии и штрафы за месяц. «Итого за месяц» учитывает их.

### Оплата водителям (зарплата и вывод средств)
- **Расчёт зарплаты** теперь берётся из журнала операций — это те же суммы, что попали в кошелёк, и та же «оплата водителю», что в себестоимости и документах. Раньше окно считало по своей формуле (км × ставка + точки × ставка): не учитывало комиссию, разовые заказы, премии и штрафы и расходилось с кошельком.
  Итого = оклад + за заказы + премии − штрафы. Показана детализация операций, кнопки «этот/прошлый месяц», экспорт в Excel/CSV.
- **Оклад за период** считается по каждому месяцу отдельно. Раньше период «17.01–14.02» делился на число дней января, и сумма была неверной.
- **Зарплатная ведомость** (Отчёты) использует тот же расчёт: появились столбцы «За заказы», «Премии», «Штрафы». **Раньше штрафы в ведомости не вычитались.** Пробег берётся из расчёта, а не прикидывается как «25 км на заказ».
- Карточка водителя: «начислено за месяц» считается тем же расчётом, в подсказке — разбивка.
- **Вывод средств:** минимальная сумма 100 ₽ проверяется и в окне, и в сервисе. Номер карты можно вводить с пробелами. Баланс проверяется по журналу операций. В истории операций хранится только маска карты (•••• 5678), а не полный номер.

Тесты: `PasswordAndFinanceTests.cs` — правила и генерация паролей, смена/сброс с обязательной сменой, премии/штрафы и баланс, проверки суммы и причины, вывод средств и маскирование карты, расчёт зарплаты, пропорциональный оклад.

## Права администратора, заказы из 1С, трекинг водителей

**Администратор**
- В карточке водителя появились вкладки «Финансы» и «Управление» с действиями для администратора: удалить или исправить операцию, удалить маршрут (заказы возвращаются в «Новые», по желанию удаляются начисления), снять один или все заказы, сменить статус, заблокировать вход, открепить ТС, удалить водителя вместе с историей.
- Все действия выполняются через `AdminDriverService`: каждое — одной транзакцией, с проверкой роли и обязательной причиной. Баланс учётной записи синхронизируется.
- Новая таблица `audit_log` — журнал действий администратора, он виден в карточке.
- Удаление водителя на странице «Водители» тоже идёт через этот сервис. Сессии водителя в мобильном приложении сразу закрываются.

**1С вместо веб-формы**
- Встроенный HTTP API (`AppHttpServer` + `AppApiRouter`, порт 5080):
  - приём заказов `POST /api/1c/orders`, повторы по `ExternalId` пропускаются;
  - статусы `GET /api/1c/statuses` в JSON или XML, с координатами водителя;
  - «где заказ» `GET /api/1c/track`;
  - доступ по ключу `X-Api-Key`.
- Готовый общий модуль 1С (`docs/1C/ОбменСАРМДиспетчера.bsl`). Со страницы «Интеграция» он сохраняется с уже подставленными адресом и ключом.
- Файлы из папки обмена подхватываются автоматически, в том числе те, что лежали там до запуска. На «Заказах» кнопка «Веб-заявки» заменена на «Загрузить из 1С».
- Старая веб-форма для клиентов (`WebOrderServer`) убрана из меню. Код оставлен, но не используется.

**Приложение водителя и трекинг**
- Мобильное веб-приложение (`Web/driver.html`), открывается в браузере телефона, установка не нужна. В нём: вход, список заказов, карта, кнопки «Начать погрузку / Выехал к клиенту / Товар передан», маршрут в Яндекс Картах, звонок клиенту, отправка GPS, режим имитации для демонстрации.
- Новая таблица `driver_locations`. Страница «Трекинг водителей» показывает карту (обновление раз в 5 секунд), список водителей на линии, расстояние и время прибытия, поиск «Где заказ?».
- В «Моих заказах» водителя в программе используется та же логика (`DriverTaskService`).
- `Открыть_доступ_для_телефонов.bat` открывает порт для телефонов (urlacl и брандмауэр).
- `SchemaUpgrader` теперь создаёт в старой базе недостающие таблицы, не только столбцы.

**Тесты:** добавлено 29 тестов (`AdminTrackingApiTests.cs`): действия администратора и журнал, GPS и время прибытия, цепочка действий водителя, сессии и блокировка после неудачных входов, все маршруты HTTP API (ключ 1С, импорт, дубли, статусы JSON/XML, трекинг), создание новых таблиц в старой БД.

## Расчётный листок, новый внешний вид, карта трекинга, маршрут в приложении водителя

**1. Удаление и исправление операций в «Расчёте зарплаты» (администратор).**
Окно переименовано в «Расчётный листок». Под таблицей операций у администратора есть кнопки **«Изменить сумму…»** и **«Удалить операцию…»** (также двойной щелчок по строке — исправление суммы). Причина обязательна, действие записывается в журнал администратора, баланс водителя пересчитывается, листок обновляется сразу. Строка «Оклад» — расчётная, а не операция, поэтому её удалить нельзя. Диспетчеру кнопки не показываются, а сервис отклоняет попытку.
Технически: `PayrollLine` получил `TransactionId`, и окно вызывает `AdminDriverService.DeleteTransactionAsync / ChangeTransactionAmountAsync`.

**2. Внешний вид — без «ИИ-стиля».**
- Палитра «Деловая»: стальной синий `#2F5D8A`, графитовая боковая панель, нейтральный серый фон, приглушённые цвета состояний. Индиго, градиенты и тени убраны.
- Скругления уменьшены до 3 px, кнопки — обычным начертанием.
- Эмодзи убраны из всех надписей, кнопок, статусов и сообщений: программа, приложение водителя, карта, веб-страница заказа.
- Расчётный листок оформлен как бухгалтерский документ: шапка (водитель, условия оплаты, период), таблица «Начислено / Удержано», строка «Итого за период», журнал операций. Пять крупных цветных цифр убраны.
- Приложение водителя: строгие кнопки с текстом («Я на карте», «Выйти», «Обновить»), без эмодзи-логотипа.

**3. Ошибка 403 на карте трекинга.**
Причина: подложка грузилась с сервера тайлов OpenStreetMap, а он отклоняет запросы без адреса страницы (Referer). Встроенный браузер WebView2 открывает карту из строки (`NavigateToString`), поэтому адреса страницы нет, и сервер отдавал картинки «403 Access blocked». Карта трекинга и приложение водителя переведены на Esri World Street Map, как основная «Карта». Если Esri недоступен, подложка автоматически переключается на CARTO.

**4. Маршрут не появлялся в приложении водителя.**
Серверная часть работала: тест «маршрут → `/api/driver/me`» проходит. Причина была в окне «Построить маршрут»: в списке были только водители со статусом «Свободен», и окно само подставляло первого. Водитель, у которого уже был заказ или рейс, получал статус «В рейсе» и пропадал из списка. Маршрут молча уходил другому водителю, поэтому у driver1 ничего не появлялось.
Исправлено:
- в списке все водители, которых можно назначить (свободные и уже в рейсе), с подписью «вход в приложение: driver1»;
- водитель не подставляется сам;
- после сохранения программа пишет, под каким логином маршрут виден в приложении, и предупреждает, если у водителя нет учётной записи.

В приложении водителя:
- список обновляется каждые 8 секунд, при возврате в приложение и по кнопке «Обновить»;
- пустой список показывает, под каким водителем выполнен вход и время обновления.

Новые тесты (`PayrollAdminAndMapTests.cs`, 8 шт.):
- идентификаторы операций в листке;
- удаление штрафа с пересчётом и записью в журнал;
- исправление суммы;
- запрет для диспетчера;
- второй маршрут водителю «в рейсе» виден в приложении;
- карты не используют заблокированный сервер тайлов.
